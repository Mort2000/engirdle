# 阶段 4 真机验收矩阵（Android 后台化）

设计依据：`.scratch/mobile_lightweight_readpack_translation_design.md` §9/§14。
本仓库开发环境（WSL2，无连接设备）无法上机执行；本矩阵是交付前必须在真机上跑完的清单。模拟器可先跑通 1–6，厂商省电与锁屏长跑必须真机。

设备要求：API 31、33、35、36 各一台 + 一台激进省电厂商机型（如小米/华为/三星之一）。

## 前置

- [ ] `flutter build apk --debug`（或 release）安装成功；首启正常；
- [ ] 设置 › 翻译服务：填入测试 Key，连接测试通过；记录测试账号余额。

## 基本后台执行（§9.1/§9.2）

- [ ] 开始翻译后立刻锁屏：任务继续，通知显示「正在翻译：〈标题〉 n/m」进度条与取消动作，进度随单元推进；
- [ ] 翻译期间滑走任务（recents 上划）：任务继续；
- [ ] 全程飞行模式前先开始、再断网：任务进入等待通知（「网络不稳定，稍后自动继续」），联网后自动续跑；
- [ ] 仅 Wi-Fi / 仅充电约束：开启后分别在蜂窝与电池下 queue，work 不启动；条件满足后自动启动；
- [ ] 通知权限拒绝（Android 13+）：翻译仍进行，仅无通知；重新授权后下次任务有通知。

## 进程死亡与恢复（§8.4/§9.3）

- [ ] 第 1 个单元完成后 `adb shell am force-stop com.engirdle.mobile`：重开应用，任务从 journal 继续，不重复已计费单元（对比 DeepSeek 用量）；
- [ ] 中间单元与最后单元各重复一次 force-stop；
- [ ] force-stop 后不打开应用，等待 10 分钟（亮屏）：WorkManager 自行重投递并继续（厂商机型可能延迟，记录时长）；
- [ ] 设备重启：任务在重启后继续（WorkManager 持久化）；
- [ ] waiting_retry 期间 force-stop：退避投递由 WorkManager 在进程死亡后仍按时到达。

## 取消/暂停竞争（§9.2/§12.4）

- [ ] 通知「取消」动作（应用前台/后台/被杀三种状态各一次）：任务取消、building 集不可见、无孤儿通知；
- [ ] 请求进行中取消：迟到响应被丢弃（journal 无新增单元）；
- [ ] 任务页暂停 → WorkManager 无 pending work（`adb shell dumpsys jobscheduler` 无条目）→ 恢复继续；
- [ ] 删除正在翻译的文章：任务与 work 一并取消，无复活文章或孤儿译文。

## 双引擎与 UI（§9.2/§12.3）

- [ ] 后台翻译进行中打开应用：书架徽标与阅读页状态条随进度刷新（跨引擎观察者）；
- [ ] 翻译完成瞬间停留在阅读页：能力刷新，可切换英中/中文，阅读模式不自动切换；
- [ ] 冷启动（应用被杀时任务完成）：打开应用直接看到已翻译状态。

## 厂商省电机型

- [ ] 锁屏 30 分钟长跑：任务完成或至少持续推进（允许系统暂停后自动恢复）；
- [ ] 记录厂商机型上的实际行为差异（若与 AOSP 不一致，评估是否加入已知限制文档）。

## 回归

- [ ] 阶段 3 全部前台路径不回归：前台翻译、暂停/继续/取消、失败重试、既有 v1.1 包导入与播放；
- [ ] 后台翻译期间离线阅读、查词、保存生词正常；
- [ ] 日志（`adb logcat -s flutter`）只有 job id、状态分类与用量，无正文、译文、消息历史或密钥。

## 已知限制（无需修复，如实告知）

- Android 15+ `dataSync` 前台服务有每 24 小时累计 6 小时限制；超限任务回到等待，由 WorkManager 重调度，checkpoint 不丢（§9.3）；
- API 成功但本机提交前崩溃可能产生一次重复计费（§8.4，provider 无幂等键时无法彻底消除）；
- 上架 Google Play 前需完成 `dataSync` 特殊类型的 Play Console 申报。
