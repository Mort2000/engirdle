# Engirdle MVP 合理性与可行性评估

> 评估结论：有条件可行  
> 评估日期：2026-08-07  
> 产品方向：[产品目的](../purpose.md)  
> 评估对象：[MVP PRD](./mvp_prd.md) · [MVP 设计](./mvp_design.md)  
> 注意：许可证分析仅用于工程决策，不构成法律意见

## 1. 结论摘要

项目的用户问题、离线包边界和“原文先结构化”的核心技术路线合理。以单用户、Android 首发、受信任局域网和 PC 异步处理为边界，现有技术足以实现完整闭环，整体不存在需要研究突破才能解决的问题。

但原始范围并不算“小”：它同时包含内容管理工具、LLM 结构化生成、TTS/音频流水线、包协议、局域网服务、移动阅读器、播放器、离线词典和用户数据。对个人项目而言，应把“固定内容的纵向样机”视为 Pilot，把 PRD 中全部需求视为完整 MVP；若同时铺开所有模块，集成和体验风险会显著上升。

当前结论是“有条件可行”，而不是“可以直接按文档完整施工”。以下条件必须先验证：

1. 登记实际 PC 硬件，验证 Qwen3-TTS CustomVoice/Base 串行加载与 Base 逐句生成；
2. 用 DeepSeek API 验证“完整原文首轮 + 完整历史顺序逐段翻译”的质量、故障恢复和用量；
3. 在目标 Android 设备验证 M4A 句级区间播放；
4. 验证 Flutter 单句内选词和自定义菜单；
5. 确定词典数据源、体积、归属和再分发方式；
6. 用黄金包锁定 readpack v1 schema 和导入安全规则；
7. 确定 Android 最低版本及局域网/明文 HTTP 配置。

翻译和 TTS 模型已经锁定为 MVP 基线；这些门槛关闭前不应承诺排期、性能或语音质量，也不应把 `.tts` 参考目录接入生产构建。

## 2. 合理性评审

### 2.1 合理的核心决策

| 决策 | 评价 | 原因 |
|---|---|---|
| 阅读优先，翻译和词典按需出现 | 合理 | 与目标用户已有英语基础、希望减少中断的动机一致 |
| PC 重处理、移动端轻消费 | 合理 | 将模型环境、功耗和不稳定性留在可控端，降低移动复杂度 |
| 版本化离线包作为跨端边界 | 很合理 | 可独立演进模型、PC 实现与移动应用，也便于备份和回归 |
| 原文先分段分句，再做翻译和 TTS | 必要 | 直接消除译文、音频与原文边界猜测问题 |
| 完整原文预置上下文，再顺序逐段请求、按句返回 | 合理且质量优先 | 全文提供全局语义，逐段重发保持明确目标和句级映射；代价是请求用量和外部依赖增加 |
| DeepSeek V4 Flash 固定 API 基线，不做上下文压缩 | 在目标文章范围内合理 | 当前上下文容量显著大于文章假设；实现简单、语义信息完整，但超限时只能明确失败 |
| CustomVoice 定调、Base 逐句克隆 | 合理但待实测 | 人工锚点固定风格，Base 的复用 prompt 有利于句间一致性；结果仍受锚点与硬件参数影响 |
| 逐句 PCM、单篇音频 | 合理但待验证 | 生成边界确定，端侧简单；压缩后的精确裁剪仍需实机证明 |
| SQLite + 文件制品 | 合理 | 符合单用户规模，避免把大音频写入数据库 |
| 管理面回环绑定、LAN 面只读 | 合理 | 在无鉴权前提下显著缩小暴露面 |
| 词典独立于文章包 | 合理 | 避免重复体积，允许词典独立升级和归属展示 |

### 2.2 原文中需要校正的部分

| 原问题 | 影响 | 本次校正 |
|---|---|---|
| 愿景、需求、设计和风险混在同一文档 | 需求与实现互相覆盖，后续难以判断哪个是基线 | 拆分文档并建立冲突处理规则 |
| 写了“移动端”，技术建议却默认 Android+iOS 同时成立 | 双平台文本选择、网络权限和音频行为会扩大验收矩阵 | PRD 收敛为 Android 首发，iOS 留作后续 |
| 要求人工合并/拆分句子，却未定义可用的管理交互 | 只有 API 无法高效完成人工审校 | 增加仅本机最小管理 Web UI |
| 只要求“停止”，缺少长音频基本暂停/继续 | 连续听读体验不完整 | 增加暂停、继续和单一播放器状态 |
| 生词只引用 `article_id + sentence_id` | 文章升级后句子 ID 可能指向不同修订 | 引用加入 `revision`，并保存上下文快照 |
| 安全要求提到文件哈希，manifest 示例却没有 | Android 无法验证包内单个文件 | manifest 为每个载荷文件记录大小和 SHA-256 |
| 把 HTTP + SHA-256 隐含当作安全校验 | 攻击者可同时替换目录和包 | 明确只检测损坏，不认证发布者；限定受信任 LAN |
| 此前把翻译和 TTS 保持为候选模型 | 实施路径仍有关键歧义，无法冻结任务和制品元数据 | 根据新增决策固定 DeepSeek V4 Flash、Qwen3-TTS CustomVoice/Base 及其质量流程 |
| `.tts` 同时包含权重、实验脚本、日志和输出音频 | 若生产代码直接引用，会让构建不可复现且可能误提交大文件 | 整体加入 `.gitignore`，只作本机参考；生产运行目录与代码重新建立 |
| 词典仅列出若干来源名称 | 数据质量、混合来源和 share-alike 义务未进入交付条件 | 将数据来源与分发审计设为发布门槛 |
| 文章修订和“模型重建”混用 | 原文版本与制品版本语义不清 | 分离 `revision` 与 `artifact_revision` |

### 2.3 范围评价

完整 MVP 的范围与产品闭环一致，但并非最小验证集。建议采用两个清晰里程碑：

- Pilot：固定译文、固定音频和小型测试词典，验证包、局域网、Android 阅读/播放/选词；
- MVP：接入 DeepSeek 全文上下文/逐段翻译、Qwen3-TTS 锚点/Base 逐句生产、人工审校、生产词典、生词本和可靠性验收。

如果资源不足，优先保证“录入 → 听读包 → Android 离线阅读/播放”；生产级词典和生词本是最适合后移的完整子系统。不能为了保留“全功能 MVP”称谓而跳过原子导入、版本兼容或包安全。

## 3. 分维度可行性

| 维度 | 结论 | 主要依据 | 主要条件 |
|---|---|---|---|
| 产品价值 | 高 | 问题与使用场景具体，闭环清晰 | 需要真实连续使用验证是否值得持续生产内容 |
| 总体架构 | 高 | 单机、离线包、SQLite 和只读服务均成熟 | 先冻结契约和修订规则 |
| 文本结构化/DeepSeek 翻译 | 中高 | 官方 API 支持长上下文、多轮 Chat Completions 和 JSON 输出 | 依赖网络/API Key；必须完整重放历史并严格拒绝错误 ID |
| Qwen3-TTS 生产 | 中 | 本地已有 1.7B CustomVoice/Base 检查点与参考实验 | 性能依赖实际硬件；锚点质量、clone 一致性和部署目录需验证 |
| 音频句级定位 | 中 | 单文件裁剪有现成播放器能力 | 必须验证 AAC 编码、seek 和设备解码差异 |
| Android 阅读器 | 中高 | 结构化文本、SQLite 和本地文件能力成熟 | 长文章布局和多个交互手势需原型 |
| Flutter 选词菜单 | 中 | 框架支持自定义选择菜单 | 句子粒度、多版本 Android 和中文/英文边界需实测 |
| 安全导入与升级 | 中高 | ZIP 防护、事务和不可变目录模式成熟 | 文件系统与 SQLite 的恢复协议要做故障注入 |
| 离线词典 | 中 | SQLite 查询实现直接 | 数据清洗、体积、质量和授权是主要工作量 |
| 局域网发布 | 中高 | 静态目录/文件服务简单 | 平台权限、明文策略和受信任网络提示必须落实 |
| 后续可演进性 | 高 | 模型适配器、协议版本与制品追溯边界清晰 | 不允许移动端依赖模型专属字段 |

没有团队规模、技能结构、目标设备和 PC 硬件信息，因此无法负责任地给出日历工期。可行性结论只覆盖技术路径和范围排序，不等于进度承诺。

## 4. 关键事实核验

以下核验用于判断固定技术基线是否可进入实现，不等于已经在本项目环境完成验收：

- Flutter 官方文档提供 `contextMenuBuilder` 一类可组合的文本选择菜单能力，因此“选择文本后增加查词入口”在框架能力上成立；具体句子布局仍需原型。[Flutter 文本选择菜单说明](https://docs.flutter.dev/release/breaking-changes/context-menus)
- `just_audio` 当前 API 提供本地音频裁剪，项目文档也建议在需要定位时使用带准确 seek table 的 M4A；这支持当前候选设计，但不能替代 Android 实机听感测试。[ClippingAudioSource API](https://pub.dev/documentation/just_audio/latest/just_audio/ClippingAudioSource-class.html) · [just_audio 格式与 seek 说明](https://pub.dev/packages/just_audio)
- Android 9 起明文流量默认受限，当前 Android 文档还要求关注局域网访问权限演进，因此简单保存 `http://IP:port` 不能视为零配置能力。[Android 明文通信说明](https://developer.android.com/privacy-and-security/risks/cleartext-communications) · [Android 局域网权限说明](https://developer.android.com/privacy-and-security/local-network-permission)
- Apple 平台也要求本地网络用途说明，并对本地地址的 ATS 行为有专门配置；这进一步支持“不把 iOS 自动算入 Android MVP”的范围决策。[Apple 本地网络隐私](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) · [NSAllowsLocalNetworking](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking)
- DeepSeek 官方文档列出的模型 ID 是 `deepseek-v4-flash`，当前提供 1M 上下文与 JSON 输出；这支持“不为普通文章做滑窗”的 MVP 假设，但实现仍须对服务端超限明确失败。[DeepSeek 模型说明](https://api-docs.deepseek.com/quick_start/pricing/) · [Chat Completion API](https://api-docs.deepseek.com/api/create-chat-completion)
- DeepSeek Chat Completions 是无状态接口，多轮调用必须由客户端完整拼接并重发历史；思考模式支持 `reasoning_effort=max`，而无工具调用时不必把 `reasoning_content` 纳入后续上下文。[多轮会话说明](https://api-docs.deepseek.com/guides/multi_round_chat) · [思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode)
- Qwen3-TTS 官方说明同时提供 CustomVoice 的 speaker/instruct 风格控制，以及 Base 基于参考音频和 transcript 创建可复用 voice-clone prompt 的能力。本地 `.tts/README.md` 与实验脚本可作为实现参考，但不是构建输入。[Qwen3-TTS 官方仓库](https://github.com/QwenLM/Qwen3-TTS)
- Open English WordNet 官方数据为 CC BY 4.0；ECDICT 仓库标注 MIT，但其 README 说明数据汇集自多种既有资料；Wiktionary 再利用还涉及署名和相同方式共享条件。由此推断，词典不能只看代码仓库顶层许可证，必须审计最终导出的每一类数据。[Open English WordNet 许可](https://github.com/globalwordnet/english-wordnet/blob/main/LICENSE.md) · [ECDICT 来源说明](https://github.com/skywind3000/ecdict) · [Wikimedia 再利用条款](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use)

## 5. 风险登记

概率和影响采用高/中/低相对评级；风险关闭需要证据，不以“已有缓解方案”代替验证。

| ID | 风险 | 概率 | 影响 | 缓解与验证 | 发布条件 |
|---|---|---:|---:|---|---|
| R-TTS-01 | 两个 Qwen3-TTS 1.7B 检查点在实际 PC 上过慢、依赖冲突或显存不足 | 中 | 高 | 串行加载 CustomVoice/Base，记录 dtype、attention、实时因子和峰值资源 | 精确版本可重复安装；CustomVoice 制作锚点和 Base 代表文章生成均完成 |
| R-TTS-02 | CustomVoice 锚点风格满意，但 Base 克隆后句间音色、韵律或内容不稳定 | 中 | 高 | 固定英文锚点 transcript、保存参数/seed、复用同一完整 clone prompt并盲听长文 | 代表文章无阻断性漏词/截断，句间一致性达到个人使用可接受水平 |
| R-AUD-01 | AAC 编码或平台 seek 导致句首/句末偏移 | 中 | 高 | 生成边界测试音频，在目标设备随机播放短句、长句和相邻句 | 人工验收无明显截断或相邻语音泄漏；否则冻结协议前调整布局 |
| R-SEL-01 | Flutter 多句富文本与系统选择菜单冲突 | 中 | 中高 | 实现一屏长文原型，覆盖单词、短语、标点和滚动后选择 | 目标 Android 版本可稳定在单句内选择并打开查词 |
| R-DICT-01 | 词典体积、查询质量或授权无法接受 | 高 | 高 | 为每个字段建立来源台账，构建精简样本并检查常见词/短语 | 最终数据源、版本、归属和分发规则书面锁定 |
| R-TRN-01 | DeepSeek 合并、漏掉或错误匹配句子 | 中 | 中高 | 完整文章上下文、严格 schema/ID 集合校验、失败段落重试和人工审阅 | 测试集无静默错配，任何不一致均阻止发布 |
| R-TRN-02 | 完整历史逐段重发增加延迟、用量，或极端长文超过服务限制 | 中 | 中 | 记录每轮 token/请求元数据；MVP 接受成本，超限明确失败 | 代表长文可完成；没有滑窗、截断或静默换模型 |
| R-TRN-03 | DeepSeek 服务、余额、网络或模型 ID 变化阻断生产 | 中 | 中高 | 分类处理 401/402/429/5xx/超时，记录安全 checkpoint，恢复后只重试当前段 | 故障不污染已接受历史，恢复后无需重译全部成功段落 |
| R-KEY-01 | API Key 被提交、记录或发送到非官方端点 | 低中 | 高 | 环境/秘密存储注入、日志脱敏、官方 endpoint 允许列表和仓库扫描 | 仓库/日志/制品无 Key，生产请求只到官方 endpoint |
| R-BLD-01 | 生产实现隐式依赖被忽略的 `.tts` 脚本或权重 | 中 | 高 | 模型迁移到应用数据目录，适配器测试使用 fake，在无 `.tts` 环境构建 | 移除 `.tts` 后安装、测试、构建成功且产物清单无该目录 |
| R-REV-01 | 更新文章后生词或当前内容指针损坏 | 中 | 高 | 不可变修订、上下文快照、升级故障注入 | 升级/删除测试后生词仍可查看，旧版本在提交前可用 |
| R-ZIP-01 | 恶意或损坏包越界写入、耗尽空间或污染数据库 | 低中 | 高 | 允许列表、双重大小计数、路径规范化、临时目录和事务 | 恶意包矩阵全部拒绝且无目标外写入/半导入 |
| R-LAN-01 | 无鉴权 HTTP 泄露内容或被篡改 | 中 | 中高 | 默认关闭、只读、绑定受控地址、显式风险提示、限制局域网地址 | 管理端不可从 LAN 访问；威胁模型在 UI 和文档明确 |
| R-OPS-01 | 长任务崩溃后状态不一致或重复消耗资源 | 中 | 中 | 任务租约、阶段检查点、幂等缓存和工作区清理 | 各阶段故障注入后可重试且不误发布 |
| R-RGT-01 | 文章、声音、模型或词典缺少再分发权 | 中高 | 高 | 权利字段、精确版本、归属制品和发布范围限制 | 未完成审计的内容不进入可再分发版本 |
| R-SCOPE-01 | 单人并行开发所有子系统导致长期没有可用闭环 | 高 | 高 | Pilot 纵向切片、阶段门槛、每阶段可运行交付 | 先通过 Pilot，再开始生产词典和高级质量工作 |

## 6. 验证门槛

### G0：环境与目标冻结

输入：实际 PC、Android 设备和网络环境。  
产出：硬件清单、操作系统、可用存储、Android 最低版本、代表设备和 10 篇测试文章。  
通过条件：后续所有性能与兼容性结论都有明确测试环境。

### G1：协议纵向切片

输入：手写 `article.json`、固定 M4A 和最小目录。  
产出：v1 schema、黄金包、PC 构建器、Android 安全导入与三种阅读模式。  
通过条件：飞行模式可读可播，损坏包被拒绝，升级失败保留旧版本。

### G2：移动高风险交互

输入：长文章和有清晰边界提示音的测试音频。  
产出：Flutter 选词菜单原型、单句/连续播放原型、目标设备结果记录。  
通过条件：单句内选词稳定；随机句播放无明显截断或串句；状态切换无双播放器竞态。

### G3：生产端模型基准

输入：DeepSeek API Key、同一分句语料、实际 PC、CustomVoice/Base 精确检查点和本地参考流程。  
产出：完整历史请求记录、翻译结构化成功率/用量、版本化声音锚点、Base 逐句耗时/资源峰值、失败样本和盲听记录。  
通过条件：`deepseek-v4-flash` 质量配置、CustomVoice 声音配置和 Base 部署参数被锁定；适配器可从安全 checkpoint 重试；无 `.tts` 时测试与构建成功。

### G4：词典与权利审计

输入：候选英英/英中数据集和拟保留字段。  
产出：字段级来源台账、许可证/归属页面、精简 SQLite、体积和查询样本报告。  
通过条件：数据可按预期方式分发，常用词与词形查询达到个人使用可接受水平。

### G5：完整 MVP 发布演练

输入：全量实现与 PRD 验收数据集。  
产出：从空环境到离线消费的演练记录、失败注入记录、软件/模型/数据清单。  
通过条件：PRD 发布清单全部关闭，无未接受的高影响风险。

## 7. 决策建议

### 7.1 现在可以确定

- 保留“PC 生产 + readpack + Android 消费”的架构。
- 采用不可变文章修订和独立制品修订。
- 先做固定制品的 Android 纵向切片，再接真实模型。
- 翻译固定使用 DeepSeek V4 Flash：先发送完整原文，再携带完整历史按顺序逐段重发和翻译，不做上下文压缩。
- TTS 固定使用 CustomVoice 人工选定锚点，Base 通过完整 voice-clone prompt 逐句生成。
- `.tts` 整体忽略并排除于构建；实际模型放入应用管理的本地运行目录。
- 管理 UI 仅本机开放，局域网服务默认关闭且只读。
- 词典独立安装，生词保存上下文和释义快照。

### 7.2 现在不应确定

- 不应在未知硬件上承诺 Qwen3-TTS 的生成速度、显存占用或锚点克隆质量。
- 不应在试听前固定 CustomVoice speaker、instruct、锚点文本或 seed。
- 不应为降低 DeepSeek 调用成本而在 MVP 中引入滑窗、摘要、上下文裁剪或模型降级。
- 不应在实机测试前冻结 AAC 参数和句级容差。
- 不应只凭仓库顶层许可证决定词典可再分发性。
- 不应把 Flutter 等同于已经完成 Android+iOS 双平台兼容。
- 不应在 v1 尚无黄金包时开始为未来增量更新做复杂抽象。

## 8. 最终判断

在 Android 首发、受信任局域网、单用户和分阶段交付的约束下，方案在产品和工程上都合理，技术可行性为中高。DeepSeek 的长上下文能力和本地 Qwen3-TTS 参考资产使指定流程具备实现基础；主要不确定性集中在 API 会话质量/用量、Base 对人工锚点的复现、实际硬件表现、压缩音频边界、Flutter 选择交互以及词典数据治理。

建议将 G0–G3 视为是否继续完整 MVP 的决策点。若四项通过，跨端架构、DeepSeek 会话和 Qwen3-TTS 生产链路的返工风险已显著下降；若任一失败，应在包 v1 和移动数据模型冻结前调整部署参数或范围，但不得静默违反已确定的质量策略。词典授权 G4 则是任何超出纯个人本地使用范围之前的硬性门槛。
