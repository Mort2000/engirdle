屏幕目的

把“下载 → 外层校验 → 安全解压 → manifest/引用校验 → 事务写库 → 原子切换 → 清理旧制品”的完整链路状态显式化，让用户在任何失败点都知道本机数据是安全的。用户文案只暴露阶段名 + 友好提示，哈希、临时路径、格式版本号、`staging/` 等实现细节仅落入调试日志，不在 UI 中展示。

交互说明

  • 04A：下载到临时文件并显示进度；完成后先核对目录声明的大小与 SHA-256，失败可重试、绝不进入导入（MOB-DL-001）；用户文案只说「下载完成后会自动校验完整性 / 校验失败：文件不完整或损坏」，不展示哈希前缀或临时文件名。
  • 04B 步骤 1–2 对应 MOB-IMP-001：允许列表布局（manifest/article/attribution/audio）、拒绝路径穿越、重复路径、链接与超限（候选上限：ZIP 512 MiB / 展开 1 GiB / 64 条目，见 design §6.5）；用户文案收敛为「检查包结构与大小 / 解包内容」两步。
  • 步骤 5 对应 MOB-IMP-002：临时目录 + 数据库事务，全部成功才切换当前版本指针，失败回滚并保留旧版本；启动时按 staging/moving/committed 状态恢复未完成操作；用户文案为「保存到本机」。
  • 步骤 6 对应 MOB-IMP-003：切换成功后异步清理无引用旧制品；清理不影响生词中的上下文快照；用户文案为「清理旧版本」。
  • 未知主版本包（如 readpack 2.0）在下载完成后的校验阶段直接拒绝并提示「包格式不支持」（NFR-COMP-001）——UI 不再有「格式版本」字段。

错误反馈约定

下载失败归类「下载错误」、包结构问题归类「包格式 / 资源超限错误」、写库失败归类「数据库错误」，文案与屏幕 02 的分类风格一致；具体技术原因（哈希值、路径、版本号）写入日志，不进入用户提示。
